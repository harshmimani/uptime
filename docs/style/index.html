Colour

Near-black base, three surfaces that get lighter as they come closer, neutral greys, BCG green for progress and completion only, and one amber for a failed save. The primary button is off-white, not green: it's the loudest thing on screen without spending green, which then turns up only when something is done.

WCAG 2.2 AA, every pair the components use

Computed live from the CSS on this page, using the same list as tests/contrast.test.js. Text needs 4.5:1; borders, focus rings and progress marks need 3:1. "Glow max" is the brightest the moving green light can make a background.

Type

Archivo, the self-hosted subset variable font the app already ships (33 KB). Big titles and numbers use its condensed width, so digits get taller in the same space and read at arm's length. All numbers use tabular figures, so a counting timer never wobbles. Scale: ×1.25 from a 16 px body.

Space, radii, depth

A 4 px grid, a 16 px page gutter, 48 px minimum tap targets and 64 px for Start and Log set. On a dark base, depth is three things together: a lighter surface, a soft shadow below and a faint light edge on top.

Motion

Fluid and physical, but short: the user is between sets, not watching a show. Every animation reports a change of state, and everything moves with transform and opacity only. With Reduce motion on, nothing travels; changes cross-fade in under 0.2 s.

What it says

Letters rise into place: today's session has arrived. 28 ms per letter, 600 ms each, so "Upper A" lands in under 0.8 s.

Numbers count up: progress built since last time. Tabular figures keep the width steady.

Green only on progress: the week ring, the streak. The Start button stays off-white.

Light and grain move by transform, on a 14 s cycle; both stop with Reduce motion.

Set-logging controls

Bottom third of the set screen, in the order the thumb reaches them: weight, reps, then Swap and All exercises one row up and lighter, then Log set, prefilled with today's target so most sets are one tap.

Why it's built this way

Weight keys are 56 px and the value rolls up or down with the change, so a sweaty miss-tap is obvious.

Reps chips: the selected one inverts (off-white), not green: choosing isn't completing.

Log set restates the numbers it will save, so there's nothing to double-check.

Exercise progress in the header: done exercises are green, the current one fills grey set by set.

Rest timer

The ring fills grey as rest runs and turns green with a single pulse when it's over: rest done is a completion. It's built on an end time, so it's right after a screen lock, a call or an app switch, and the sweep is one compositor animation, not a JS loop.

Try it

A real 1:45 rest is running. Use the short one to see the finish. Lock your phone mid-rest and come back: the time is still right.

Set-complete animation

One tap, four things in 0.4 s: a green disc grows from the thumb and the button says what was saved, the set drops into the log, the exercise bar fills a step, and an Undo line rises from the bottom. A short buzz on phones that support it. Then rest starts by itself.

    Sequence

    0 ms press: button scales to 97%.

    240 ms Undo line rises. 1.1 s the button returns to "Log set 2" and rest begins.

    Rotation-advance animation

    After the summary's Done, Home shows the rotation moving on: the finished session gets a green tick, the highlight slides to the next one, the session name sets itself anew, and the week count ticks up. Nothing is ever "missed"; the line just moves forward.

    Buttons in every state

    Hover and press use an overlay whose opacity changes, plus a 3% press-in, so feedback is instant and never repaints the fill. Focus is a 2 px off-white ring with a 3 px gap, visible on every surface. Loading keeps the label for screen readers. Disabled stays readable.

    Empty and offline states

    Empty states say when something will appear, not that something is missing. Offline, the app works exactly the same, so there's no offline banner; only something that truly needs a connection says so. A failed save is the one thing that uses amber, and the set stays on screen until it's saved.

    Desktop ambient

    On a laptop or desktop with a mouse, a few very soft green lights drift behind the page and lean towards the pointer. It's drawn on a canvas a tenth of the screen's size, loaded after the page is idle, and only when the screen is wide, the pointer is fine, Reduce motion is off and Data Saver is off. Phones and tablets never download it.
